# drums-pool

Many drumsd hosts behind one drumsd-compatible API. Point the SDK (or the gateway) at the pool instead of one drumsd:

    export DRUMS_URL=http://pool:7080 DRUMS_TOKEN=<pool token>
    import drums; c = drums.connect(); env = c.create("osworld-ubuntu", task="...")   # unchanged SDK

    drums-pool --config pool.json

## What it does
| | |
|---|---|
| hosts | from `hosts` in the config or `POST /pool/v1/hosts` (`name, url, token_file, region, cpus, max_envs, reclaim_orphans`); `POST /pool/v1/hosts/{name}/drain` stops new envs and removes the host once empty |
| health | `GET /v1/health` of every host every `health_interval_s` (2 s); 2 failed polls = suspect (no new envs), no good poll for `dead_after_s` (10 s) = dead |
| placement | the healthy host with the most headroom: the tightest of memory (MemAvailable - memory promised to creates in flight and to envs younger than `young_env_s` - `mem_floor_pct` of RAM), CPU (load1 / cpus vs `max_load_per_cpu`) and slots (`max_envs`). Memory per desktop is learned per host. Blocked placements are counted by binding constraint (`pool_place_blocked_total{reason}`) |
| warm slots | `warm_per_host` ready desktops of `warm_image` per host; a create of that image takes one (a task's setup runs on it) |
| backpressure | a create waits in a FIFO queue for capacity instead of a refusal (`X-Drums-Queue-Timeout`, default `queue_timeout_s` 900); a host's own 429/503 (drumsd admission control) is absorbed: the host is skipped for `refuse_penalty_s` and the create placed again. 503 `queue_timeout` only when the wait runs out |
| leases | per env `idle_timeout_s` / `ttl_s` (create body, as drumsd), enforced by the pool; the host gets lease + `host_lease_margin_s` as a backstop |
| failover | when a host dies, requests in flight to it end at once; with `failover: "replace"` its envs are recreated on healthy hosts (ahead of the queue) and answer 409 `episode_lost` until a reset, which continues on the new host; a reward from the lost episode is never returned. Saved states on a dead host answer 410 `state_lost`. A host that comes back is swept of orphans before it takes envs again |
| ids | envs `pe-<boot>-<n>`, saved states `ps-<boot>-<n>`; records carry `pool: {host, region}` and no host-local `url` |
| health for gateways | `/v1/health` reports version, image_sha256, criu, limits and lease defaults only when every healthy host agrees (else ok=false): a gateway's runtime-fingerprint check keeps working |
| metrics | Prometheus at `/metrics` (bearer token): request/upstream/overhead latency by op, queue, creates, verify validity, per-host saturation, failovers, lost episodes, leases, health RTT |

Not provided: high availability of the pool itself (one process; its state is in memory), cross-host migration of a
live env (a lost episode is reported, not hidden), placement of saved states on other hosts (a fork's children and
creates from its state stay on its host).

Dashboards and alerts: `pool/deploy/` (Grafana JSON generated by `gen_dashboard.py`, Prometheus `alerts.yml`).
Tests: `cargo build -p drums-pool && python3 crates/drums-pool/tests/test_pool_sdk.py` (the released SDK against fake hosts).
